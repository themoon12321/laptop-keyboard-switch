# 笔记本内置键盘热开关

外接键盘叠在笔记本上会误触内置键盘？这个工具让你**一键截断内置键盘的全部输入**
（外接键盘、鼠标、触摸板完全不受影响），再一键恢复。支持按键级豁免（比如保留滚轮）、
开机自启、状态记忆——不需要重启，随时切换。

## 系统要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 1809+ / Windows 11，**x64 或 x86** |
| 处理器 | ⛔ **ARM64（骁龙等）不支持**（驱动无 ARM64 版本） |
| 内存完整性 | 需**关闭**（设置 → Windows 安全中心 → 设备安全性 → 内核隔离）。开启时驱动被拒载，最坏会导致所有键盘失效。setup 会自动检测并警告 |
| 权限 | 安装时需要一次管理员授权（UAC）+ 重启一次；日常使用零弹窗 |
| 其他 | ⛔ 蓝牙键盘不在拦截范围内（Interception 驱动不支持）；企业管控电脑（EDR）可能拦截驱动安装 |

## 快速开始（新机器）

1. 整个文件夹拷到目标电脑（任意路径，支持中文/空格）
2. 若压缩包是微信/网盘/浏览器下载来的：右键文件夹 → 属性 → 勾选「解除锁定」（没有该选项就跳过）
3. 双击 **`setup.cmd`** → UAC 点「是」→ 等待安装完成（自动：预检环境 → 装驱动 → 修复冷启动问题 → 鼠标保护 → 建快捷方式和自启）
4. **重启电脑**
5. 重启后托盘出现键盘图标即工作。按 **Ctrl+Alt+K** 试一下切换！

命令行用户也可以：管理员 PowerShell 运行 `setup.ps1`（参数：`-SkipDriver` 只装用户组件；`-KeepMouseFilter` 保留鼠标侧绑定；`-YesToAll` 无人值守）。

## 日常使用

| 操作 | 方式 |
| --- | --- |
| 切换截断/恢复 | **Ctrl+Alt+K**（任意键盘，全局生效） |
| 打开软件面板 | 桌面「键盘开关」，或双击托盘图标 |
| 只留外接 / 恢复内置 / 紧急恢复 / 扫描豁免 / 改快捷键 | 都在面板和托盘右键菜单里 |
| 看状态 | 托盘图标：键盘=正常，红🚫=已截断，黄⚠=未识别；悬停有文字提示 |
| 开机行为 | 自动启动并恢复上次的开关状态 |

三条切换途径互补，任何状态下都不会把自己锁死：
系统热键（外接/未截断键盘可用）、**内置键盘紧急组合**（截断时在内置键盘上按同组合也能恢复，仅左侧 Ctrl/Alt）、面板/托盘。

## 按键扫描与豁免（救回滚轮/多媒体键）

截断是按键级的，可以把个别键「豁免」（截断时照常工作）：

1. 先「恢复内置」
2. 面板 →「扫描按键(豁免)…」→ 把内置键盘的按键逐个按一遍（滚轮等非标准键也能扫到）
3. 勾选要豁免的键 → 保存。配置持久化，随时可「清除全部豁免」

紧急组合键永远受保护，不会被豁免掉。

## 换新电脑 / 多台电脑

- 直接把整个文件夹拷过去跑 `setup.cmd` 即可；`install.ps1` 会自动检测 ini 缓存来自其他机器并重置
- 内置键盘识别是通用策略：句柄特征（`MSFT0001` / `ACPI\`）命中即接管，**全部命中的设备一起纳入**（内置键盘拆成多个设备的机型不漏）；都不命中时（部分游戏本内置键盘走 USB），看门狗会在开机后弹出**按键识别向导**（按一下内置键盘 → 列出识别结果 → 你确认后才生效，防止误选外接键盘）

## 故障排查

| 症状 | 处置 |
| --- | --- |
| **键盘卡住/键位错乱（如 ESC 变 Win 键）** | 这是"修饰键卡死"。v5 已内置幽灵键修复（截断期间收到无按下的抬起会自动补发抬起），恢复时还会主动清除残留修饰键。若仍发生，运行 **`紧急恢复键盘.lnk`**（或 `KeyboardToggle.ahk release`）强制放行全部键盘 |
| **退出后键盘仍被截断** | v5 用 PID 文件保证单实例，退出/释放都会 `SetState(false)`+退订+清修饰键。仍异常就运行「紧急恢复键盘」 |
| 托盘黄⚠一直「未识别」 | 看门狗每 2 秒重试，失败 4 次后约 5 分钟弹一次识别向导；也可面板「重新识别」 |
| 日志 `devlist count=0` | 驱动没加载：确认 setup.cmd 完整跑过（尤其 SYSTEM_START 那步）且重启过 |
| 切换无反应 | 面板看真实状态（与底层订阅严格一致）；日志 `app\KeyboardToggle.log` |
| 识别到外接键盘 | 交互向导必须勾选确认才生效；点取消即不保存。「重新识别」可重来 |
| 滚轮/多媒体键失效 | 面板 →「扫描按键(豁免)」扫一遍，勾选要保留的键 |
| 鼠标异常 | 本工具机制上不触碰鼠标（安装时已拆除鼠标侧绑定） |

**命令行诊断**（不打开面板）：

```powershell
$ahk = "app\AutoHotkey\AutoHotkey64.exe"; $s = "app\KeyboardToggle.ahk"
& $ahk $s status      # 查看状态
& $ahk $s release     # 应急放行（杀守护 + 清修饰键）
& $ahk $s identify    # 只识别并显示设备
```

## 可靠性设计（v5）

| 机制 | 解决的问题 |
| --- | --- |
| **整设备订阅**（每台内置键盘 1 次） | 取代 v4 的 511 次单键订阅：不会部分成功、不会半截断、切换瞬间完成 |
| **豁免键回调重注入** | 豁免功能保留（滚轮等），但不再依赖逐键订阅 |
| **幽灵键修复** | 截断瞬间按住的修饰键，其抬起被吞会导致系统永久认为 Win/Ctrl 按住 → ESC 变 Win+ESC。检测到无记录的抬起立即补发 |
| **恢复 = 退订 + SetState(false) + 清修饰键** | 三重硬放行，杜绝"显示已恢复但实际仍截断" |
| **PID 单实例 + 启动清场** | 杜绝多守护进程互相争抢订阅（"退出后仍截断"的主因） |
| **订阅前身份核验（编号+句柄）** | 休眠/重连后设备号被外接键盘顶替时绝不误订阅 |
| **全有或全无** | 任一设备订阅失败 → 全部回滚 + `SetState(false)`，状态永不虚报 |
| **2 秒身份轮询 + 设备变更消息** | 设备消失/改号后 2 秒内发现并重新接管 |
| **19 项仿真测试 + 干跑集成测试** | 每次改代码可回归，不触碰真实键盘 |

## 卸载

- **保留驱动**（日常无影响）：运行 `uninstall.ps1`（快捷方式/自启清理，守护退出时键盘自动放行）
- **彻底卸载**：运行 `uninstall-all.ps1`（弹 UAC：卸驱动 + 还原设备类过滤器 + 清配置日志），完成后重启

## 工作原理（简述）

内置键盘在多数机型上被标记为「关键系统设备」，禁用/移除/停服务的设备级方案都会被系统拒绝（本项目实测过全部路径）。因此采用 **Interception 内核过滤驱动 + AutoHotkey v2**：驱动挂在键盘类驱动之下，脚本对内置键盘按扫描码逐键订阅并吞掉——豁免键不订阅即内核直通，外接设备从不经过订阅。附带两处加固：驱动服务改**系统启动**（修复官方安装的冷启动不加载缺陷）、鼠标侧过滤绑定拆除（机制上保证不碰鼠标）。

│     ├─ install-interception.exe   驱动安装器

```powershell
powershell -ExecutionPolicy Bypass -File tests\dryrun.ps1
```

## 已知边界

- Windows 专用；ARM64、HVCI 开启、蓝牙键盘、企业 EDR 环境见「系统要求」
- 休眠/唤醒后拦截设备号可能变化（上游已知问题）：守护每 30 秒核验设备**编号+句柄**，失效自动重新接管并重建订阅
- 多用户快速切换场景下，每个会话各自独立（订阅按进程隔离），文档提醒避免两会话同时操作
