# 安装、升级与卸载

适用于 Windows x86/x64。ARM64 不支持；开启 HVCI/内存完整性时安装停止，脚本不会关闭安全功能。驱动需管理员权限及重启。虚拟机、企业安全策略、USB/I2C 内置键盘和不同 OEM 驱动仍需逐机验证。

## 新电脑

1. 下载分发 ZIP 并完整解压到固定、当前用户可写的文件夹。不要直接在压缩包里启动，不要把正在使用的目录搬走。
2. 双击 `diagnose.cmd`：只读检查架构、HVCI、Interception 服务和当前键盘 PnP ID，不安装驱动、不监听输入。先断开外接键盘，必要时插拔对比，确认哪个是内置设备。
3. 双击 `setup.cmd`。只有唯一状态正常的 ACPI 键盘才作为自动安装候选；多个候选或 USB/I2C 内置设备必须指定。安装前记录原始过滤器；官方安装器短暂写入键盘/鼠标类过滤器后，立即恢复这两类的原值，再只给选定内置设备增加 `keyboard`。不在线重启键盘或鼠标，不修改 USB 电源策略。
4. 重启电脑，然后双击 `start.cmd`。首次运行正常直通，替代规则和自启默认关闭。界面提示确认设备时，仅勾选本机内置键盘；没有可靠候选时用内置键盘按两个不同键做非阻断识别。
5. 先验证外接键盘正常输入，再在面板中测试内置屏蔽与恢复，最后配置替代规则和所需的自启。

明确指定内置设备（把示例替换为自己 `diagnose.cmd` 输出中的实际 ID，不要照抄其他机器）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -DeviceId 'ACPI\YOUR_DEVICE\YOUR_INSTANCE'
# 多个确认属于内置键盘的 PnP 实例：在 PowerShell 中执行
.\setup.ps1 -DeviceId @('ACPI\YOUR_DEVICE\INSTANCE1','ACPI\YOUR_DEVICE\INSTANCE2')
# 只读预览，不会请求 UAC 或更改系统
.\setup.ps1 -DryRun
# 明确需要开机启动时
.\setup.ps1 -AutoStart
```

设备级过滤器写入受到系统权限限制时安装会失败，保留安装前记录，不能声称已经生效。此时先按卸载步骤恢复，再排查；不会自动改为过滤所有外接设备。实际驱动挂载只能在重启后验证。

已有完整 Interception 时直接复用，不修改其服务和过滤器，也不会在卸载时删除。若已有驱动没有绑定内置键盘，识别会失败，需要由原安装的管理者处理；本工具不会擅自迁移其他软件的驱动。多个副本可共享驱动，但固定的用户自启项一次只供一个副本使用。

用户配置和机器缓存保存在 `app/KeyboardToggle.ini`、`app/KeyGestures.ini`，都不纳入新版本 Git 或分发包。新用户不会继承开发者电脑的句柄、屏蔽状态和坏键规则。升级仅补齐缺少的配置文件，不覆盖已有规则。设备缓存只在写入它的电脑上使用；新设备或新片段必须再次确认。

如果 AHI 同时返回多个完全相同的硬件句柄，应用拒绝选择，避免把同型号外接键盘一起屏蔽。这种情况需先解决设备级绑定或识别歧义，不能仅凭缓存的 VID/PID 判断物理设备。

## 安装记录与失败恢复

- 机器层：`%ProgramData%\LapKeySwitch\installs\<安装路径哈希>\machine.json`。
- 当前用户：`%LOCALAPPDATA%\LapKeySwitch\installs\<安装路径哈希>\user.json`。
- 提权助手失败详情：机器记录同目录的 `machine-error.txt`。

机器快照在首次调用驱动安装器之前写入，重复安装不会覆盖最初快照。记录含机器身份和安装路径，拒绝拿到另一台电脑或另一路径回滚。用户记录保存原始快捷方式内容及自启项；恢复时不会无条件覆盖后来被其他程序修改的值。

部分安装失败会记录为 `failed`；断电可能停在 `prepared`。保留目录和记录，运行 `uninstall-all.cmd`。没有安装成功就不要启动屏蔽功能。失败恢复也必须重启验证。完整安装链只经过模拟验证，发布前仍应在有恢复手段的干净 Windows 测试机完成一次真实安装/重启/卸载/重启验收。

## 完整卸载

1. 保留原目录；运行 `uninstall-all.cmd -Purge`。它请求本项目释放输入并退出，恢复属于本安装的用户入口，删除本地运行配置和日志，按机器快照撤销过滤器改动，并卸载本项目新装的驱动。原本就存在的驱动保持原样。
2. 重启电脑。驱动可能处于等待重启删除状态，不能在重启前承诺卸载干净。
3. 运行 `verify-uninstall.cmd`。检查本安装进程、入口和拥有的驱动/绑定；任何一项失败都会报错，保留记录继续排查。
4. 验证通过后，如需清除安装记录，用当前账户的管理员 PowerShell 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\verify-uninstall.ps1 -PurgeReceipts`。仅删除本安装的记录，不递归删除共享目录。
5. 手动删除解压后的项目文件夹，以及自行下载的 ZIP。脚本不会在自身运行中递归删除项目，以免误删 Git 历史或放在里面的其他文件。

只卸载用户组件、保留驱动和规则：`uninstall.cmd`。共享驱动后来被其他工具使用时：`uninstall-all.cmd -KeepDriver -Purge`；这是有意保留共享依赖，不能称为驱动删除。

检测到其他副本仍在使用驱动、未知设备也绑定它、第三方改动冲突或卸载器返回错误时，完整卸载会停止。不会为了显示成功而强行删除共享驱动。安装后第三方增加的非 Interception 过滤器会保留，恢复仅撤销本项目的改动。

## 旧版迁移

旧版没有真正的安装前快照，无法推导它覆盖前的服务/过滤器值。不能把现在的状态备份后宣称恢复到最早状态。原用户可直接使用更新后的应用与规则；运行新版 setup 会把“此刻已有驱动”视为共享依赖，保留它。

无新版记录的旧安装，`uninstall.cmd` 只清理能核实完整目标路径属于本项目的入口；完整卸载会拒绝删除未知来源的驱动。若确定旧驱动是专门为本工具安装且不被其他软件使用，需要先审查旧排障记录和当前设备级绑定，制定一次性迁移/卸载方案，不能直接套用其他机器的设备路径。

历史曾经修改过的 USB 电源策略、厂商设置、第三方工具配置不属于新版安装改动，新版也不擅自重置它们。
