## 外接键盘主输入区失效

用户反馈蓝牙/2.4G 键盘连接正常，音量键可用但主输入区失效，上一轮排障后有所恢复。代码与排障记录支持“键盘过滤路径有关”的判断，但不足以证明单一根因：媒体控制与普通键盘输入可能经过不同接口，连接成功不等于主输入通路可用。

当前读取到的配置：

- 键盘类 UpperFilters 为 `kbdclass`，不包含 Interception 的 `keyboard`。
- 内置 `ACPI\MSFT0001\4&3155e47&0` 设备级 UpperFilters 为 `keyboard`。
- `_unfilt2.txt` 记录 10 月 25 日移除类级绑定，HID 外接键盘设备重启成功。
- `_devfilter.txt` 记录设备级绑定写入成功，但内置键盘重启返回 50，提示等待系统重启。
- 审查时最后开机时间仍为 10 月 19 日。没有重启后的验证数据，不能把注册表值当作实际驱动栈已完成迁移的证据。

旧 KbCore v6 注释把“省略 SetState(true)”解释为杜绝全局残留，这个推论不成立。读取随包 DLL 的方法 IL（未实例化驱动 Manager）确认：`SubscribeKeyboard` 自身会先调用 `SetFilterState(false)`，再调用 `SetFilterState(true)`。上游也有同样逻辑：[Manager.cs](https://github.com/evilC/AutoHotInterception/blob/master/C%23/AutoHotInterception/Manager.cs)。底层过滤设置通过当前上下文和设备谓词作用到选定设备：[interception.c](https://github.com/oblitum/Interception/blob/master/library/interception.c)。本轮修正了注释和文档，不再作“任何进程死亡都不会残留”“绝不影响外接”的保证。

## 确认并处理的问题

| 问题 | 处理 |
| --- | --- |
| setup 重装会重新绑定整个键盘类，验证步骤还拒绝已有的设备级安装 | 检测并保留已有设备级绑定，跳过官方驱动重装，验证接受该布局 |
| 完整卸载只清类级绑定，遗漏设备级 keyboard | 卸载驱动之前移除每个键盘设备上的对应过滤项，保留其他项，失败则中止 |
| OnTick 在 Reset 清掉 blocked 后据此恢复，覆盖用户原意 | 独立保存期望状态，失联安全放行，设备返回后重新应用原意 |
| 反订阅或 SetState(false) 失败仍清空记录并报恢复 | 保留失败订阅，显示未确认状态，阻止旧映射重新激活 |
| PID 文件只是定位，没有原子单实例保护，启动强杀同名脚本 | 使用命名互斥锁，转发前核对完整路径，不再启动即强杀 |
| 同号设备换成外设到下一次轮询前仍可能被处理 | 收到输入及定时输出时再核对句柄和类型，异常设备先透传并请求重新识别 |
| 已缓存部分 ACPI 设备后遗漏其他内置片段 | 对 ACPI 缓存补全其他匹配片段，仍保留显式 USB 缓存选择的优先级 |
| 紧急组合可被豁免重注入 | 组合中的修饰键与目标键始终不按豁免放行 |
| 扫描、切换和新的替代功能会争抢同一个整设备订阅 | 同一核心管理观察、替代和截断模式，扫描结束恢复目标状态 |
| 面板多行按钮沿用第一行 Section，可能越界 | 每行重新定位，隐藏 GUI 中检查所有控件均处于客户区内 |
| status 无守护时会启动输入处理 | 仅报告未运行，不启动守护 |
| 旧干跑测试使用固定临时目录、实际系统热键及 Send | 唯一测试目录，替换输入 API，禁用热键/Send/快捷方式修改，隐藏 GUI，限定清理路径 |
| 已检测 HVCI 不兼容仍允许无人值守继续装驱动 | 停止安装，-YesToAll 不跳过兼容性门禁，不修改系统安全设置 |

## 新功能

只用于内置键盘的可配置长按/双击替代。默认 X→Z（600ms）、句号/>→斜杠/?（600ms）、上排 3→4（3000ms）。短按保留原键；Shift、CapsLock、当前布局及输入法照常解释目标键。Ctrl/Alt/Win 快捷键优先直通，其他按键插入时先放行原键以保护打字顺序。触发一次输出一次，不重复补发；断开、截断、退出时取消延迟字符。

Fn 不支持通用模拟，不对固件层功能键模式作承诺。普通 F1–F12 可以配置为目标键。规则写在独立的 `app/KeyGestures.ini`；当前默认启用，但本轮没有启动真实守护进程。
